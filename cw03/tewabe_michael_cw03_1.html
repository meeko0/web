Exercise 2: Debugging CSS

My Debugging Analysis

Finding 1: Font stack with no generic fallback

Original: font-family: "Times New Roman";

Fix: font-family: "Times New Roman", Times, serif;

Why: If Times New Roman is not installed (common on Linux and some phones), the browser falls back to its own default font, which may not even be a serif. A generic family at the end of the stack guarantees the intended style of font.

Finding 2: Headings h1, h2, and h3 share one size

Original: h1, h2, h3 { font-size: 2.5em; }

Fix: h1 { font-size: 2.5em; } h2 { font-size: 2em; } h3 { font-size: 1.5em; }

Why: With one shared size, every heading level looks identical, so readers lose the visual hierarchy the HTML structure describes. Also, em is relative to the parent, so a heading inside a larger parent grows further. Giving each level its own size restores the outline.

Finding 3: Missing semicolons on the last declarations

Original: box-sizing: border-box and color: red with no semicolon

Fix: box-sizing: border-box; and color: red;

Why: The last semicolon in a rule is technically optional, so the page renders as-is. But when I added another declaration after box-sizing: border-box, the browser read both lines as one invalid value and dropped them, which DevTools showed as struck-through. Always ending declarations with a semicolon prevents that silent failure.

/*Corrected CSS*/
body {
    font-family: "Times New Roman", Times, serif;
    margin-left: 20%;
    margin-right: 20%;
    text-align: justify;
    background: ivory;
    color: red;
}

h1 {
    font-size: 2.5em;
}

    font-size: 2em;

.artist { font-size: 14pt; font-family: Arial, sans-serif; font-weight: bold; color: moccasin; }
.song-title { font-size: 14pt; font-family: Arial, sans-serif; font-weight: normal; color: khaki; }
.album { font-size: 12pt; font-family: Arial, sans-serif; font-weight: normal; color: khaki; }
.year { font-size: 12pt; font-family: Arial, sans-serif; font-weight: bold; color: ivory; }

.verse {
    font-size: 14pt;
    font-family: 'Trebuchet MS', sans-serif;
    font-weight: bold;
    color: gold;
    margin-left: 2cm;
    margin-right: 2cm;
}

.chorus {
    font-size: 14pt;
    font-family: 'Trebuchet MS', sans-serif;
    font-weight: bold;
    font-style: italic;
    color: gold;
    margin-left: 4cm;
    margin-right: 4cm;
}

Keeping presentation in an external file separates content from design: the HTML only says what each line is (verse, chorus, artist), and one stylesheet decides how it looks. Any other page that links lyrics.css gets the same styling, and a design change happens in one place instead of on every page.

UG 02: Pixel Budget Under Constraint

Target: a rendered outer width of exactly 420px at a 900px viewport, without writing width: 420px.

Before: content-box panel
.budget {
    box-sizing: content-box;
    width: 380px;
    padding: 18px;
    border: 2px solid;
}
/*outer width = 380 + 18 + 18 + 2 + 2 = 420px*/
After: border-box panel
.budget-bb {
    box-sizing: border-box;
    width: calc(380px + 2 * 18px + 2 * 2px);
}
/*switching to border-box alone shrinks the panel to 380px,
   because padding and border now fit inside the width.
   calc() adds them back: 380 + 36 + 4 = 420px */

UG 03: Breakpoint Failure Study

My test: every quick link at the top of this page must be visible without horizontal scrolling.

Failure: the quick links sit in a flex row with flex-wrap: nowrap and white-space: nowrap, so the row cannot shrink below its content width. First failing width: ___ px (drag the DevTools device toolbar down until a horizontal scrollbar appears).

Measured value: computed width of .quick-links ul at the failing width = ___ px, which is wider than the viewport.

Repair (one media query):

@media (max-width: 999px) {
    .quick-links ul {
        flex-wrap: wrap;
    }
}

The query only applies at 999px and below, so the desktop layout above 1000px is unchanged.

Reflection: 2–3 sentences tying the overflow to the computed width, and why wrapping fixes it.
